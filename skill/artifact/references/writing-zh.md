# 中文写作规范

写中文内容时读。前半部分是规则，后半部分是改写示例。规则的依据是 GB/T 15834—2011《标点符号用法》、GB/T 15835—2011《出版物上数字用法》和《中文文案排版指北》，以及大量“读起来像机器写的”中文文本的共同毛病。

## 目录

1. 排版：空格、标点、数字、专有名词
2. 用词与语法：常见病句
3. AI 腔：要删掉的词和句式
4. 克制：强调、夸张与升华
5. 连贯：段落之间怎么接
6. 改写示例
7. 自查命令

## 1. 排版

### 1.1 空格

- 中文与英文之间加一个半角空格：`使用 GitHub 登录`，不写 `使用GitHub登录`。
- 中文与阿拉伯数字之间加空格：`部署到 3 台服务器`，`2026 年 10 月`。
- 数字与单位之间加空格：`20 GB`、`200 ms`、`3 个月`。例外：百分号和度数紧贴数字，`35%`、`90°`。
- 全角标点前后不加空格：`在 GitHub 上，你可以……`，逗号前后都不留空。
- 链接、行内代码与中文之间同样加空格，例如：运行 `make build` 编译。

一份文档内必须统一。`art check` 会报告缺少空格的位置。

### 1.2 标点

中文句子里用全角标点：，。、；：？！“”‘’（）《》……——。

| 符号 | 用法 | 常见错误 |
|---|---|---|
| 句号 。 | 陈述句结束 | 用半角 `.`；列表里有的加有的不加 |
| 顿号 、 | 句内并列的词语：`北京、上海、广州` | 用逗号分隔并列词语；用顿号分隔并列的分句 |
| 逗号 ， | 句内停顿 | 一逗到底，整段只有一个句号 |
| 冒号 ： | 提示下文 | 一句里连用两个冒号；“例如:”用半角 |
| 引号 “” | 引用、特指；内层用 ‘’ | 用直引号 `"…"`；用引号表示讽刺或“所谓的” |
| 书名号 《》 | 书、文章、报刊、法规、影视作品 | 用于软件、产品、公司名：《微信》《Git》都是错的 |
| 括号 （） | 注释、补充：`服务等级协议（SLA）` | 中文语境用半角 `()` |
| 省略号 …… | 六个点，占两个字 | 写成 `...` 或 `。。。` |
| 破折号 —— | 占两个字，表示解释或转折 | 写成 `-` 或 `—`；用得太多（见第 4 节） |
| 浪纹线 ～ | 数值范围：`3～5 个工作日` | 全文时而 `～` 时而 `-` |
| 间隔号 · | 外国人名：`艾伦·图灵` | |

其他规则：

- 标题末尾不加句号。
- 列表项是完整句子时加句号，是短语时不加；同一个列表保持一致。
- 不叠用标点：不写 `！！`、`？？`、`？！`。
- 完整的英文句子、英文专有名词内部用半角标点：`他说：“Stay hungry, stay foolish.”`

### 1.3 数字

- 计量、统计、编号用阿拉伯数字：`响应时间 230 ms`、`共 14 个接口`、`第 3 章`。
- 成语、惯用语、概数、带感情色彩的说法用汉字：`三五天`、`一方面`、`十几个`、`第一时间`。
- 年份写全：`2026 年`，不写 `26 年`。日期全文统一一种格式：`2026 年 10 月 17 日` 或 `2026-10-17`。
- 大数用“万”“亿”：`1.2 万`、`3.5 亿元`；不写 `12,000` 和 `1.2万` 混用。
- 同一类数据保留相同的小数位：`12.5%、8.0%、3.2%`。
- 范围两端都带单位或都不带：`3～5 秒`，不写 `3 秒～5`。

### 1.4 专有名词与缩写

- 用官方写法：GitHub、JavaScript、TypeScript、Node.js、PostgreSQL、iOS、macOS、Wi-Fi、HTTP、API、Kubernetes。
- 不用随意缩写：不写 `JS`、`k8s`、`PG`，除非读者群体都这么叫，并且第一次出现时写全称。
- 第一次出现的缩写给出全称或中文：`首字节时间（TTFB）`。
- 中文没有斜体。需要强调时用加粗（少量）或着重号；HTML 中可用 `text-emphasis: filled dot`。

## 2. 用词与语法

### 2.1 虚化动词

“进行、加以、予以、做出”后面接双音节动词，多数时候是多余的。

- `对接口进行了优化` → `优化了接口`
- `对数据加以分析` → `分析数据`
- `做出调整` → `调整`

### 2.2 “的”字堆叠和过长定语

一个短语里出现三四个“的”，或者定语长到读者要回头找中心词，就拆开。

- 原：`这是我们团队针对上个季度的用户反馈的数据的分析结果。`
- 改：`这份结果分析的是上季度的用户反馈。`

### 2.3 翻译腔

- `作为一个开发者，你需要……` → `开发者需要……` 或直接写 `你需要……`
- `是一个很重要的问题` → `很重要`
- `对于新用户来说，……` → `新用户……`
- `基于以上分析，我们可以得出……` → `所以……`
- `在性能方面有所提升` → `性能提升了`（再写清提升多少）
- 被动句只在不知道或不必说出施动者时用：`这个接口被很多服务调用` → `很多服务调用这个接口`

### 2.4 成分残缺与搭配不当

- 缺主语：`通过这次迁移，使系统延迟降低了一半。` → `这次迁移让系统延迟降低了一半。`
- 动宾不搭：`提高了用户的满意和留存` → `提高了用户满意度和留存率`
- 赘余：`大约 3 个左右`、`目前现在`、`过分溺爱`、`第一次首发`。
- 一句话里主语中途换人：`我们上线了新版本，在第二天出现了故障` → 写清楚是谁出现了故障。

### 2.5 指代与关联词

- “它”“这”“该”“其”要能一眼看出指什么。离先行词超过一句，就重复名词。
- 关联词表达的逻辑必须成立：
  - “因为 A，所以 B”：A 真的导致了 B，而不只是先后发生。
  - “虽然 A，但是 B”：A 和 B 确实有转折，不是并列。
  - “不仅 A，而且 B”：B 比 A 更进一层。
- 关联词不要成对堆满全文，能靠语序表达的就不加。

### 2.6 的、地、得

- 定语 + 的 + 名词：`稳定的版本`
- 状语 + 地 + 动词：`逐步地迁移`（很多时候可以省掉“地”：`逐步迁移`）
- 动词 + 得 + 补语：`跑得很快`

### 2.7 称呼和视角

- 一份文档里，对读者用“你”或“您”，选一个，不混用。
- 作者自称用“我们”或省略，不要一会儿“我们”一会儿“本文”一会儿“笔者”。
- 正式文档不用网络用语和口头禅：`拉满`、`绝绝子`、`yyds`、`搞定`、`小伙伴们`。

## 3. AI 腔

下面这些写法会让读者立刻觉得“这是机器写的”，同时几乎不传递信息。写完后逐项检查。`art check` 会标出其中一部分。

### 3.1 空泛的大词

赋能、抓手、闭环、底层逻辑、顶层设计、颗粒度、心智、打法、组合拳、护城河、全链路、全方位、多维度、深层次、一站式、无缝。

这些词都在替代一个具体的说法。问自己：它具体指什么？然后写那个具体的东西。

- `为业务全方位赋能` → 写清楚做了哪件事、谁因此能做到什么。
- `形成数据闭环` → `用户的点击记录每天回流到推荐模型，第二天生效`。

### 3.2 夸张的形容

极致、颠覆、革命性、重磅、震撼、史诗级、划时代、前所未有、完美、天花板、质的飞跃、指数级。

用数字和事实代替：

- `性能得到了质的飞跃` → `P99 延迟从 1.8 秒降到 240 毫秒`
- `前所未有的体验` → 删掉，或者写出用户具体能做到的事。

### 3.3 套话连接

值得注意的是、值得一提的是、需要指出的是、不难发现、不难看出、由此可见、综上所述、总而言之、总的来说、众所周知、毋庸置疑、显而易见、让我们一起来看看、接下来让我们深入探讨。

删掉它们，句子基本都更好。真要提醒读者注意，直接说要注意什么：`迁移前必须先备份`。

### 3.4 宏大开场

`随着人工智能技术的飞速发展……`、`在数字化转型的大背景下……`、`在当今这个信息爆炸的时代……`

读者打开这一页是为了一个具体问题。第一句就回答它，或者交代读者需要的背景。

### 3.5 拔高和升华

`这不仅是一次技术升级，更是一次理念的革新。`、`开启了新篇章`、`未来可期`、`具有重要意义`、`彰显了团队的实力`、`为……注入新的活力`、`让我们共同期待`。

结尾停在信息上：结论、数据、待决定的事项、下一步谁做什么。意义由读者自己判断。

### 3.6 句式套路

| 套路 | 例子 | 怎么改 |
|---|---|---|
| 先立靶子再推翻 | `这不是一个技术问题，而是一个管理问题。` | 直接说是什么：`这个问题出在排期上。` 全文最多用一次 |
| 三连排比 | `更快、更稳、更省心` | 选一个有数据支撑的说 |
| 设问自答 | `那么问题来了：为什么会慢？答案是……` | `慢的原因是……` |
| 冒号揭晓 | `原因只有一个：缓存失效。` | `原因是缓存失效。` |
| 破折号插入语 | `这个方案——尽管看起来复杂——其实很好实现。` | 拆成两句 |
| 对仗金句 | `数据驱动决策，体验定义产品。` | 删掉 |
| 段末小结 | 每段最后一句重复本段大意 | 删掉 |

### 3.7 结构套路

- 每个小标题前放一个 emoji。
- 本来连贯的论证被拆成一串只有半句话的要点。
- 每节都是“首先……其次……最后……”。
- 每段第一句都加粗。
- 内容不是顺序关系，却编上 01、02、03。
- 主标题和每个小标题都是“话题：结论”的冒号结构。
- 标题上方放分类小标签、面包屑，标题下方放“面向某某读者 / 约 8 分钟”这类元信息串。
- 文末一个“总结”，把全文再说一遍。

列表只用于真正并列、可以独立阅读的条目；有因果、有递进的内容写成段落。

### 3.8 讨好与客套

`好问题！`、`希望这篇文章对你有所帮助！`、`如果你有任何问题，欢迎随时交流！`

成品页面里不出现这些话。

### 3.9 编造的具体

为了显得具体而编数字、引语、案例、用户评价，是最严重的问题。数字必须有来源；用户没有给数据而页面需要示例时，在图表或表格旁写明“示例数据”。

## 4. 克制

**强调有预算。** 一屏之内加粗不超过两三处，整页感叹号为零。所有东西都强调，等于没有强调。

**形容词让位于事实。** “大幅”“显著”“明显”后面如果能跟一个数字，就只写数字。

**不强调无关紧要的事。** 篇幅和视觉权重分配给读者最需要的信息。三句话能说完的背景，不要占一节。

**结论只说到证据支持的程度。** 一次实验的结果写“这次测试中”，不写“证明了”。不确定就写不确定，并说明还缺什么信息。

**不替读者表态。** 不写“令人振奋的是”“遗憾的是”，把事实摆出来。

---

## 5. 连贯

- 每段第一句交代这一段要说什么，并和上一段接上。接的方式是内容本身：上一段讲问题，这一段第一句就讲原因或方案，不需要“接下来”“此外”来过渡。
- 同一个东西从头到尾用同一个名字。第一次叫“任务队列”，后面就不要变成“作业池”“消息队列”。
- 前后数字一致：摘要里的 37%，正文里不能变成 36.8%（除非说明了取整）。
- 时间、视角一致：全文用过去时叙述已发生的事，用“将”“计划”叙述未来的事。
- 读一遍，遇到需要回头重读的地方，就改那一句。

## 6. 改写示例

### 示例一：报告开头

原：

> 随着公司业务的快速发展，系统面临着前所未有的挑战。值得注意的是，在过去的一个季度中，我们对缓存架构进行了全方位的优化升级，取得了显著的成效！这不仅是一次技术上的突破，更是团队协作的结晶。

改：

> 第三季度，我们把会话缓存从单机 Redis 迁到了三节点集群。迁移后，高峰期登录接口的 P99 延迟从 1.8 秒降到 240 毫秒，全季度没有再出现因缓存宕机导致的登录失败（第二季度有 4 次）。

改动：删掉时代开场、套话、感叹号和升华；补上做了什么、结果是多少、和什么比。

### 示例二：功能介绍

原：

> 🚀 **极致性能**：采用业界领先的架构，为您带来丝滑流畅的使用体验。
> 💡 **智能推荐**：基于先进的 AI 算法，精准洞察用户需求，全面赋能业务增长。

改：

> 搜索结果在 100 毫秒内返回，包括有 2000 万条记录的项目。
>
> 输入框下方会根据你最近打开的文件给出建议；不需要时可以在设置中关闭。

改动：去掉 emoji 和加粗标签；每条只说用户能感知到的一件事；补上关闭方式。

### 示例三：结论段

原：

> 综上所述，本次迁移不仅解决了性能问题，更为未来的发展奠定了坚实的基础，开启了系统架构的新篇章。让我们共同期待更好的明天！

改：

> 迁移已经完成，旧集群将在 11 月 15 日下线。还有两件事需要决定：是否给报表服务也接入新集群（估计 3 人日），以及告警阈值是否从 500 毫秒收紧到 300 毫秒。

改动：结尾停在待办和待决定的事项上。

### 示例四：技术说明中的病句

原：

> 通过对日志的分析，使我们发现了问题的原因是由于连接池的配置不合理的原因导致的。

改：

> 日志显示，连接池上限设成了 10，而高峰期有 40 个并发请求，多出的请求都在排队。

改动：补上主语；删掉重复的“原因”；把“不合理”换成具体数值。

### 示例五：“不是……而是……”与破折号

原：

> 这不是一次简单的改版——而是一次从用户视角出发的彻底重构。我们不是在做加法，而是在做减法。

改：

> 这次改版删掉了 12 个使用率低于 1% 的设置项，把注册流程从 5 步缩短到 2 步。

## 7. 自查命令

发布前在目录里运行，逐条看命中的地方是否需要改：

```bash
grep -rnE "赋能|抓手|闭环|底层逻辑|全方位|多维度|一站式|无缝|极致|颠覆|革命性|重磅|震撼|前所未有|质的飞跃" .
grep -rnE "值得注意的是|值得一提的是|不难发现|综上所述|总而言之|众所周知|毋庸置疑|让我们" .
grep -rnE "随着.{0,20}发展|时代背景下|在当今|不仅.{0,30}更是|新篇章|未来可期|具有.{0,6}意义|注入.{0,4}活力" .
grep -rnE "！|——|不是.{1,30}而是" .
```

`art check` 会做同样的检查，并报告中英文空格、半角标点、直引号、重复标点和加粗过多的问题。
