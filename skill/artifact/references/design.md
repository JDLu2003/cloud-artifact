# 视觉设计

决定配色、字体、版式时读。运行环境的硬规则（主题变量写法、响应式）在 `page-contract.md`，这里讲怎么做出不像模板的页面。

## 1. 先判断需要多少设计

设计是默认要做的，区别只在力度：

- **实用型**：报告、方案、技术文档、会议纪要、数据页。要有清楚的层级、讲究的间距和配色，但不要大标题首屏、不要花哨动效。多数请求属于这一类。
- **表现型**：活动页、作品展示、小游戏、要分享出去的工具。可以有鲜明的视觉主张，在一处大胆。

拿不准时选实用型。排得好的普通页面永远合格；用力过猛的页面经常不合格。

用户或项目已经有设计规范（品牌色、组件库、现有页面）时，照着用。优先级：用户的原话 > 已有规范 > 你的选择。

## 2. 从主题本身取材

- 先明确三件事：主题是什么、给谁看、这一页的主要任务是什么。
- 与众不同的视觉选择来自主题自己的世界：它的材料、工具、行话、单位、惯用的文档格式。给财务分析师看的季度报表和给小学生看的科普页，配色、字体、密度都应该不一样。
- 每个页面至少放进一个只有这个主题才有的细节，作为内容而不是装饰：真实的单位和量程、行业里的表格惯例、专业术语、真实的数据格式。
- 全程使用真实内容。不用 lorem ipsum，不用“标题文字”“这里是描述”。

## 3. 先写设计变量

动手写页面前，在 `<style>` 最上面的 `:root` 里定下：

```css
/* 版式：左侧窄目录 + 右侧单栏正文，图表与正文同宽 */
:root {
  /* 颜色：4–6 个有名字的变量 */
  --bg: …; --surface: …; --fg: …; --muted: …; --line: …; --accent: …;
  /* 字体：至少两个角色 */
  --font-body: …; --font-display: …; --font-mono: …;
  /* 间距与字号：一套比例，全页只用这几档 */
  --s1: 4px; --s2: 8px; --s3: 16px; --s4: 24px; --s5: 40px; --s6: 64px;
}
```

然后所有颜色、字体、间距都从变量里取。写完变量，对照主题检查一遍：如果换一个完全不同的主题，这套变量也照样能用，说明选得不够具体，改它。

## 4. 字体与排版

- 中文正文用系统字体栈（见 `page-contract.md`），不加载中文网络字体。
- 字体家族一到两个就够。两个时要有明显区别，例如宋体标题配黑体正文。
- 中文正文：字号 15–17px，行高 1.7–1.85，段落间距约 1em。
- 行宽：中文每行 30–40 个字。段落、列表这类正文元素本身加 `max-width: 38em`，即使外层容器为了放宽图表而更宽；英文约 65 个字符。这条是硬约束，宽屏上一行五六十个字会明显难读。
- 定一套字号比例并严格遵守，例如 13 / 15 / 17 / 21 / 28 / 36px。
- 标题加 `text-wrap: balance`，避免最后一行只剩一两个字。
- 中文不用斜体。不用全大写标签。不要在标题里只把一个词换成别的颜色或斜体。
- 正文左对齐。只有短标题、封面、单个数字可以居中。
- 数字成列出现时用 `font-variant-numeric: tabular-nums`。

## 5. 颜色

- 一个主色占大部分视觉面积，一两个辅助色，一个强调色。不要所有颜色平均分配。
- 中性色带一点主色的色相，比纯灰更有整体感。纯白和近黑也可以用，但要是有意的选择。
- 强调色只给真正需要注意的东西：主要按钮、当前选中、图表里要说明的那条线。
- 语义色（成功、警告、危险）与强调色分开，不算在配色里。
- 检查对比度：正文与背景至少 4.5:1，大字至少 3:1。暗色主题单独检查。

## 6. 版式

- 用 flex/grid 的 `gap` 控制同级元素的间距，不要给每个元素单独加 margin。
- 重复出现的元素保持一致：同一行的卡片，边距、基线、内边距相同；同类信息出现在同一位置。
- 列数要让内容填满，不要出现一行只有一个孤零零的卡片。
- 边框、底色、圆角、阴影都表示“这是一个独立的对象”。按角色使用，只给需要区分出来的元素，不要给每个区块都套一张卡片。
- 首屏按内容定高，不用 `100vh` 撑满。用户打开页面时，第一眼就能看到这一页最重要的东西。
- 页面加载完就是完整的。不要让内容停在 `opacity: 0` 等滚动触发。

## 7. 动效

- 默认不加。只在需要吸引注意或说明变化时用。
- 一处精心设计的动效，胜过每个区块都淡入上移。
- 响应用户操作的动效（展开、切换、确认）是好的，它说明了发生了什么变化。
- 尊重 `prefers-reduced-motion`。

## 8. 数据页和工具界面

这类页面是被扫视和操作的，重点从排版转到信息设计：

- 先摘要后细节：最上面是读者最关心的几个数，下面才是明细。
- 状态用形式表达，不只用数字：标签、色块、图标，让需要注意的东西一眼可见。
- 大数字卡片只在这些数字就是页面重点时使用。
- 可交互的元素要看起来可以点：按钮像按钮，链接像链接，有悬停和焦点状态。
- 工具打开时就处于可用状态：有用户的真实数据就用，没有就放一组标明“示例”的数据，不要给一个空壳。

## 9. 这些是模板化的痕迹

下面这些做法出现在大量生成的页面里，与主题无关，读者一看就觉得是套模板。用户明确要求时照做；用户没指定时，不要把自由度花在它们上面：

- 米黄底色（接近 #F4F1EA）+ 高对比衬线大标题 + 赤陶色强调。
- 近黑背景 + 一个荧光绿或朱红强调色。
- 白底 + 紫到蓝的渐变首屏。
- 报纸式的细线分栏、零圆角、密集多栏。
- 所有内容切成一样大的圆角卡片，统一的浅灰阴影，渐变色块做装饰。
- 卡片一侧的彩色竖条，标题下的装饰短横线，页面顶部或侧边的装饰色条。
- 标题上方的小标签：全大写英文、分类名、面包屑（`工程笔记 / HTTP`）。
- 用分隔符连起来的元信息串：`作者 · 日期 · 阅读时间`、`面向后端工程师 / 约 8 分钟`。作者和日期确实需要时，分开放，不加分隔符；“约 N 分钟读完”不需要。
- 主标题写成“主题：副标题”，每个小标题都写成“话题：结论”。
- 用 emoji 当图标或小标题。
- 内容不是顺序关系，却加 01 / 02 / 03 编号。
- 所有东西居中。
- 首屏一个巨大的数字、一行小标签、再配一条渐变。
- 每个区块滚动时淡入上移。
- 默认使用 Inter 或 Space Grotesk。

## 10. 收尾

- 质量底线不用宣传，但必须达到：手机宽度可用、键盘焦点可见、尊重减少动效设置、颜色对比合格、明暗主题都正常、没有文字溢出或被截断。
- 出门前照一下镜子，摘掉一件饰品：最后看一遍，删掉一个不服务于内容的装饰。
