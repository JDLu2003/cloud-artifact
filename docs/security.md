# 安全模型

## 要防什么

1. **artifact 里的脚本攻击服务本身**。artifact 是 agent 生成的任意 HTML 和 JavaScript，可能有意或无意地包含恶意代码。它不能借用读者的登录状态调用管理接口，也不能读取其他 artifact。
2. **未授权访问**。没有密钥不能发布；一个用户不能读写另一个用户的 artifact；私有 artifact 和历史版本只对所有者和管理员开放。
3. **资源耗尽**。单个用户或单把密钥不能写满磁盘、拖垮服务。
4. **凭据泄露后的损失**。数据库泄露不应直接暴露可用的密钥和密码；泄露的密钥可以立即吊销。

## 内容隔离

- 所有 artifact 内容只从 `/c/{id}/v{n}/{令牌}/…` 提供，响应头带：
  `Content-Security-Policy: sandbox allow-scripts allow-forms allow-popups allow-popups-to-escape-sandbox allow-modals allow-downloads allow-pointer-lock`
  其中**没有** `allow-same-origin`，页面运行在不透明源里：读不到 cookie，发往本站的请求被浏览器视为跨站，带 `SameSite=Lax` 的会话 cookie 不会附带。
- 查看页再用带 `sandbox` 属性的 iframe 嵌入内容，双重限制。
- 脚本、样式、字体只允许来自本服务和白名单 CDN；`form-action 'none'` 禁止表单提交到任何地方；`frame-ancestors` 只允许本服务嵌入。
- 内容响应带 `Referrer-Policy: no-referrer`，避免路径中的签名令牌通过 Referer 泄露给外部网站。
- 可选的 `ARTIFACT_CONTENT_ORIGIN` 把内容放到独立的域名下，即使浏览器的沙箱实现有缺陷，也拿不到后台的 cookie。

## 访问控制

| 资源 | 规则 |
|---|---|
| 发布、修改、删除 | 有效的 API Key；只能操作自己的 artifact（管理员可以操作全部） |
| 当前版本的内容 | 持链接可看、公开：任何人；私有：需要签名令牌 |
| 历史版本的内容 | 需要签名令牌，只签发给所有者和管理员 |
| 历史、源码、对比页 | 登录的所有者或管理员 |
| 管理接口 | 登录会话 + CSRF 令牌 + 同源校验；用户、设置、审计日志只对管理员开放 |

签名令牌是 HMAC-SHA256（密钥见 `ARTIFACT_SECRET`），绑定 artifact ID、版本号和过期时间（12 小时），放在 URL 路径里，使页面内的相对路径资源自动带上。

他人 artifact 的接口一律返回 404，不暴露是否存在。

## 凭据

- API Key 格式 `art_` + 36 位随机字符（约 214 位熵），数据库只存 sha256。签发时只显示一次。
- 后台密码用 bcrypt（cost 11）。改密码后该用户的所有会话失效。
- 会话令牌 32 字节随机数，数据库只存 sha256；cookie 为 `HttpOnly`、`SameSite=Lax`，HTTPS 下加 `Secure`；有效期 14 天。
- 登录失败和无效 Key 按 IP 限流（每分钟约 10 次和 30 次）。
- 停用用户会立即使其会话和密钥失效。

## 资源限制

- 每个用户：存储（同一用户内按内容去重计算）、artifact 数、单文件大小、单版本大小与文件数、每分钟请求数、每分钟发布数。管理员可在后台按用户调整。
- 全局：请求体上限；磁盘剩余低于阈值时拒绝写入；回收站到期自动清理；无引用的文件每小时回收一次。
- 容器层面：compose 默认限制内存 256 MB、CPU 1 核。

## 上传校验

- 路径规范化后拒绝：绝对路径、`..`、空段、隐藏文件或目录、控制字符和 `: * ? " < > | # %`；最多 8 层、200 字符。
- 文件类型按扩展名白名单判断；未知扩展名只接受 UTF-8 文本，其他二进制拒绝。
- 所有内容以 `X-Content-Type-Options: nosniff` 返回。

## 审计

发布、编辑、回滚、修改信息、删除、恢复、彻底删除、签发与吊销密钥、用户变更、设置变更、登录成功与失败都会记录时间、用户、密钥、IP 和对象。保留最近 5 万条。

## 已知限制

- 默认部署是 HTTP。公网使用请加 HTTPS（见 deploy.md），否则密钥和会话在传输中是明文。
- “持链接可看”依赖链接的随机性。把链接转发出去，就等于把访问权转发出去；需要严格控制时改为私有。
- 首次启动时管理员密码和初始 Key 会打印到容器日志，建议登录后修改密码，并视情况吊销初始 Key。
